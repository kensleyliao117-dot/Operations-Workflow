# Operations-Workflow V1.0 前端产品需求文档（PRD）

**文档版本：** V1.0 Draft 1  
**项目名称：** Operations-Workflow  
**产品类型：** AI 辅助内容运营工作流系统  
**首发平台：** 小红书  
**运行环境：** 本地  
**前端技术：** Vue 3 + Vite  
**后端技术：** FastAPI + LangGraph + PostgreSQL  
**文档状态：** 待需求评审

---

## 1. 产品概述

### 1.1 产品定位

Operations-Workflow 是一套 AI 辅助内容运营系统。

用户上传自己的产品资料，系统通过 RAG 理解产品，结合小红书爆款内容分析、人工 Prompt 和历史运营经验，辅助生成文案及图片。

用户审核后，可以将内容发布到小红书。系统根据作品后续运营数据提炼经验，用于下一次内容生成。

### 1.2 V1.0 核心目标

1. 让用户通过可视化界面操作完整内容生产工作流。
2. 降低产品资料管理、内容生成和发布的操作复杂度。
3. 支持多用户使用，确保每个用户的数据独立。
4. 保留人工审核权，避免 AI 未经确认直接发布。
5. 形成从内容生产到运营经验复用的业务闭环。

### 1.3 目标用户

需要运营一个或多个产品的小红书内容创作者、运营人员或小型团队成员。

V1.0 以个人账号操作为主，不提供团队协作、角色权限分配和管理员后台。

### 1.4 版本边界

**V1.0 包含：**

- 注册、登录和账号会话管理
- 多产品及产品资料管理
- 产品 RAG 知识入库
- 小红书爆款采集和 AI 分析
- 人工 Prompt 管理与应用
- AI 文案与图片生成
- 平台规则与自定义规则检查
- 人工审核、修改与版本管理
- 小红书发布
- 工作流和任务状态查看
- 运营数据及经验积累状态展示

**V1.0 不包含：**

- 管理员后台
- 多平台内容发布
- 云端部署管理
- 团队协作和权限分级
- 独立运营数据分析大屏
- 独立 AI 经验管理页面
- 复杂报表和数据可视化中心

## 2. 前端页面信息架构

### 2.1 页面结构

登录前：

- 登录页面 Login.vue
- 注册页面 Register.vue

登录后：

- 产品管理 Products.vue
- 内容生成 Generate.vue
- 审核发布 Review.vue

全局公共区域：

- 导航菜单
- 当前登录用户信息
- 退出登录
- 消息提示
- 加载与错误反馈
- 工作流状态显示

### 2.2 页面导航原则

**产品管理 → 内容生成 → 审核发布**

这是用户的主要操作路径。

用户可以随时切换页面，已保存的任务、审核结果和生成内容不能因为切换页面而丢失。

## 3. 用户账号模块

**页面：Login.vue / Register.vue**

### AUTH-001 用户注册

**功能说明：** 新用户创建独立账号。

**UI 元素：**

- 用户名输入框
- 邮箱输入框（以实际后端注册字段为准）
- 密码输入框
- 确认密码输入框
- 注册按钮
- 返回登录入口

**交互规则：**

1. 用户填写注册信息。
2. 前端完成必填、格式和两次密码一致性检查。
3. 点击注册后提交后端。
4. 注册成功后跳转登录页面。
5. 账号冲突或注册失败时显示具体错误信息。

**验收要求：**

- 无效信息不能直接提交。
- 不能重复提交注册请求。
- 错误提示明确。
- 注册后的账号可以正常登录。

### AUTH-002 用户登录

**UI 元素：**

- 账号输入框
- 密码输入框
- 登录按钮
- 注册入口
- 密码显示/隐藏按钮

**交互规则：**

1. 用户输入登录信息。
2. 前端请求登录接口。
3. 登录成功后保存会话状态。
4. 进入产品管理页面。
5. 登录失败时提示错误。

### AUTH-003 JWT 会话管理

**功能要求：**

- 需要认证的接口自动附带 JWT。
- 未登录用户无法进入业务页面。
- JWT 失效时清理会话并要求重新登录。
- 用户退出后清理本地登录状态。
- 页面刷新后正确恢复或重新验证会话状态。

**安全要求：**

前端不能依靠隐藏按钮实现数据隔离，后端必须对每个请求验证用户身份及数据归属。

JWT 保存方式需要结合现有后端认证机制确定，避免不必要的 XSS 风险。

## 4. 产品管理模块

**页面：Products.vue**

### PROD-001 产品列表

**功能说明：** 管理当前用户的多个产品。

**UI 元素：**

- 页面标题「产品管理」
- 新建产品按钮
- 产品搜索框
- 产品列表
- 产品名称
- 产品简介
- 已上传资料数量
- 知识库状态
- 查看、编辑、删除入口

**交互规则：**

- 登录后展示当前用户拥有的产品。
- 点击产品进入详情。
- 没有产品时展示空状态和新建入口。
- 产品较多时支持搜索。

### PROD-002 新建和编辑产品

**产品信息：**

| 字段 | 说明 |
|---|---|
| 产品名称 | 必填 |
| 产品简介 | 简短介绍 |
| 产品特点 | 主要特征及卖点 |
| 目标人群 | 产品对应用户 |
| 补充描述 | 自由文本 |

以上是建议的产品编辑字段，最终应以现有产品模型可保存的字段为准，不重复增加已有 RAG 文档中的结构化内容。

**交互规则：**

- 点击新建弹出编辑表单。
- 保存成功后更新产品列表。
- 保存失败时保留用户已填写的信息。
- 编辑已有产品时展示原有内容。

### PROD-003 产品资料上传

**功能说明：** 支持为不同产品分别上传多个资料文件。

**UI 元素：**

- 上传区域
- 选择文件按钮
- 已选择文件列表
- 文件大小
- 上传进度
- 上传状态
- 删除入口

**状态：**

- 等待上传
- 上传中
- 上传成功
- 上传失败

**交互规则：**

1. 用户选择产品。
2. 选择一个或多个文件。
3. 点击上传。
4. 展示上传进度或处理中状态。
5. 成功后更新该产品的资料列表。
6. 失败时展示原因及可重试操作。

支持的文件格式、大小限制和批量上传数量由现有后端能力决定。

### PROD-004 RAG 入库状态

**功能说明：** 让用户知道资料是否可用于 AI 内容生成。

**UI 元素：**

- 资料名称
- 处理状态
- 处理失败原因
- 重新处理入口（后端支持时显示）

**建议状态：**

- 待处理
- 处理中
- 已入库
- 入库失败

**验收要求：**

- 不能把上传成功等同于 RAG 入库成功。
- 入库失败必须有明确反馈。
- 产品 A 的资料不能显示在产品 B 下。
- 不同用户的产品资料必须隔离。

### PROD-005 产品删除

**交互规则：**

- 删除前显示确认弹窗。
- 提示删除可能影响已有任务和知识资料。
- 只有后端确认成功后才从列表中移除。

产品删除是否级联删除资料、向量和任务，需要在联调前明确，前端不得自行假定。

## 5. 内容生成模块

**页面：Generate.vue**

这是 V1.0 的核心业务页面。

### GEN-001 选择产品

**功能说明：** 用户首先选择本次需要运营的产品。

**UI 元素：**

- 产品选择器
- 产品简介
- 产品资料数量
- RAG 就绪状态

**交互规则：**

- 只能选择当前用户的产品。
- 选择产品后加载对应产品信息。
- 缺少产品时提示先创建产品。
- 切换产品时提示未保存的任务配置可能丢失。

### GEN-002 创建内容任务

**功能说明：** 用户为一次内容生成创建任务。

**建议输入项：**

- 任务名称
- 关联产品
- 内容主题
- 内容目标
- 补充要求

**交互规则：**

1. 用户选择产品。
2. 填写任务要求。
3. 点击创建任务。
4. 后端创建任务记录。
5. 创建成功后展示任务状态。
6. 用户继续执行工作流。

### GEN-003 小红书爆款采集

**UI 元素：**

- 采集关键词输入框
- 开始采集按钮
- Chrome 连接状态
- 采集进度或运行状态
- 案例结果列表

**案例展示信息：**

- 标题
- 内容摘要
- 图片缩略图（有数据时）
- 点赞、收藏、评论等可获得的指标
- 原始作品链接
- 采集时间

**交互规则：**

1. 用户填写关键词。
2. 点击开始采集。
3. 前端显示采集中状态。
4. 采集完成后展示结果。
5. 采集失败时显示原因。
6. Chrome 未连接时提供操作指引。

前端只显示采集器实际返回的数据，不得填充虚构指标。

### GEN-004 AI 爆款分析

**功能说明：** 使用 AI 分析采集到的案例。

**分析结果建议展示：**

- 标题特点
- 内容结构
- 主要卖点
- 情绪与表达方式
- 互动引导方式
- 可参考的内容方向

**交互规则：**

- 用户选择待分析案例。
- 点击 AI 分析。
- 显示分析中状态。
- 完成后展示分析结果。
- 分析失败时可重试。

如果后端统一工作流已经自动负责采集、分析及生成，应由工作流触发一次执行，而不是要求前端重复调用内部节点。

### GEN-005 人工 Prompt

**功能说明：** 用户能够设置自己的生成指令。

**UI 元素：**

- Prompt 编辑区域
- 已保存 Prompt 选择器
- 保存、更新入口
- 应用到当前任务按钮

**规则：**

- 用户可以编辑自己的 Prompt。
- 支持将 Prompt 应用于当前内容任务。
- 保存操作必须由用户明确触发。
- AI 运营经验不能自动覆盖人工 Prompt。
- Prompt 应与当前用户关联。

如果后端已经支持多条 Prompt，前端可以通过侧边抽屉管理，无需新增独立页面。

### GEN-006 AI 文案生成

**功能说明：** 调用后端 LangGraph 工作流生成小红书文案。

**输入来源：**

- 当前产品的 RAG 信息
- 用户人工 Prompt
- 爆款分析结果
- 相关平台规则
- 历史运营经验

**UI 元素：**

- 生成按钮
- 运行状态
- 当前工作流步骤
- 生成结果区域
- 失败提示
- 查看审核入口

**交互规则：**

1. 确认当前任务。
2. 用户点击生成。
3. 前端启动后端工作流。
4. 显示工作流实际执行状态。
5. 工作流到达人工审核节点后，展示待审核内容。
6. 用户进入审核页面。

**重要限制：**

- 不能因为 HTTP 请求返回成功，就直接认为所有节点已执行完成。
- 不能在工作流执行期间重复触发同一任务。
- 生成失败不能显示虚假的成功信息。
- 页面刷新后应能根据后端任务记录恢复状态。

### GEN-007 AI 图片生成

**功能说明：** 调用已接入的千问生图能力，为内容生成配图。

**UI 元素：**

- 生图状态
- 图片预览
- 图片生成失败提示
- 重新生成入口（接口支持时）
- 查看原图入口

**规则：**

- 生成图片关联当前任务或内容版本。
- 图片不允许串到其他用户的任务中。
- 原图加载失败时展示占位和错误提示。
- 图片重新生成不得未经确认覆盖已经选定的图片。

具体生图顺序遵循后端 LangGraph，不强制设计为独立的第二条工作流。

### GEN-008 生成任务历史

**功能说明：** 方便用户恢复之前的工作。

**UI 元素：**

- 最近任务列表
- 产品名称
- 任务创建时间
- 工作流状态
- 继续查看入口

任务历史放在 Generate 页面侧边区域，不新增历史记录页面。

## 6. 审核与发布模块

**页面：Review.vue**

### REV-001 待审核内容列表

**UI 元素：**

- 待审核任务
- 所属产品
- 创建时间
- 当前审核状态
- 查看详情入口

用户只能查看自己有权限访问的任务。

### REV-002 内容预览

**展示内容：**

- 小红书标题
- 正文
- 图片
- 当前版本号
- 所属产品
- 当前规则检查结果

预览应清楚区分 AI 生成原稿和用户已经修改保存的版本。

### REV-003 人工编辑与版本保存

**功能说明：** 允许用户修改 AI 文案。

**UI 元素：**

- 标题编辑框
- 正文编辑框
- 图片预览或选择区
- 保存修改按钮
- 历史版本入口

**交互规则：**

1. 用户进入审核详情。
2. 编辑标题和正文。
3. 点击保存。
4. 后端保存内容及版本记录。
5. 页面更新版本状态。
6. 用户可继续审核。

**规则：**

- 未保存内容离开页面时进行提示。
- 保存失败不得清空已编辑文字。
- 内容版本以数据库记录为准。
- 不允许只修改前端显示却未持久化后直接发布。

### REV-004 平台规则检查

**功能说明：** 展示小红书平台规则辅助检查结果。

**UI 元素：**

- 规则检查状态
- 问题描述
- 问题所在内容
- 修改建议
- 重新检查按钮（接口支持时）

**结果建议分组：**

- 已通过
- 需要注意
- 未通过

具体等级需与后端现有规则模型一致。

用户修改文案后，原检查结果应标记为可能失效，并依照现有后端能力重新检查。

自定义规则的维护入口可以放在 Generate 的设置抽屉中，无需新增规则管理页面。

### REV-005 人工审核

**功能说明：** 用户决定是否允许内容进入发布阶段。

**操作：**

- 保存修改
- 通过审核
- 退回修改

**交互规则：**

- 审核动作调用对应后端工作流接口。
- 不能只更改前端任务状态。
- LangGraph 从人工审核暂停节点继续执行。
- 审核结果和时间应保留记录。

### REV-006 小红书发布

**功能说明：** 将审核通过的内容发布至小红书。

**UI 元素：**

- 待发布内容预览
- 目标发布账号信息（能够可靠读取时）
- 确认发布按钮
- 发布中状态
- 发布结果
- 发布记录或作品链接

**交互流程：**

1. 用户确认文案及图片。
2. 点击发布。
3. 前端弹出二次确认。
4. 用户确认后调用发布接口。
5. 展示发布中状态。
6. 根据后端确认的结果显示成功或失败。

**安全规则：**

- 禁止未经用户确认自动发布。
- 禁止重复提交产生重复作品。
- 发布状态不确定时，先查询实际结果，不直接重试。
- 不能仅凭自动化脚本点击成功就宣称真实发布成功。

### REV-007 发布状态与运营反馈

**展示信息：**

- 发布状态
- 发布时间
- 作品链接或 ID
- 已采集的运营指标
- 指标最近更新时间
- AI 经验处理状态（后端可提供时）

运营指标显示在已发布内容详情中，不新增独立数据分析页面。

实际指标采集和 AI 经验提炼继续由后端完成。

## 7. 全局交互规则

### 7.1 页面状态

所有主要业务组件必须支持：

| 状态 | UI 行为 |
|---|---|
| 无数据 | 展示空状态和下一步操作 |
| 加载中 | 展示加载提示，禁止重复提交 |
| 操作成功 | 明确反馈并刷新相关数据 |
| 操作失败 | 展示错误原因及恢复建议 |
| 无权限 | 阻止操作，不显示敏感数据 |
| 登录失效 | 清理会话并转至登录页面 |
| 长任务运行中 | 显示状态和当前步骤 |
| 网络中断 | 保留可恢复的本地编辑内容 |

### 7.2 工作流状态一致性

所有页面显示的任务状态，以后端数据库及 LangGraph 状态为准。

前端不得擅自认定：

- 文案生成成功
- 审核通过
- 内容已发布
- 运营指标已采集
- 经验已成功写入

### 7.3 操作反馈

对删除、发布等重要操作使用确认弹窗。

普通保存操作应提供明确结果，但不频繁打断用户。

### 7.4 数据隔离

所有产品、Prompt、任务、内容版本、审核、发布记录和历史经验必须归属正确用户。

前端请求不应允许用户通过任意修改 user_id 获取其他用户的数据。

## 8. UI/UX 设计要求

### 8.1 整体设计方向

建议使用桌面优先的业务管理系统布局。

视觉风格：

- 简洁、专业
- 内容优先
- 减少不必要的装饰
- 统一按钮与表单样式
- 让用户始终了解当前任务状态

### 8.2 页面布局建议

**产品管理：** 产品列表 + 产品详情 + 资料管理。

**内容生成：** 左侧任务及产品配置，中间核心操作区，右侧工作流状态和生成结果。

**审核发布：** 左侧任务列表，中间可编辑内容，右侧规则检查与审核操作。

### 8.3 重点用户体验

- 工作流阶段明确可见。
- AI 长任务不能让用户误以为页面卡死。
- 用户编辑内容时避免意外丢失。
- 审核和发布操作必须清楚区分。
- 错误提示要能够指导用户下一步操作。
- 组件和交互模式尽量统一。

### 异常分支

**资料入库失败：** 查看错误并重新处理。

**爆款采集失败：** 检查 Chrome 环境后重新尝试。

**AI 生成失败：** 保留任务记录，在后端允许的节点重试。

**审核不通过：** 继续修改并重新提交审核。

**发布结果不明确：** 查询发布记录和实际状态，避免重复发帖。

## 11. 测试与验收标准

### 11.1 账号与权限

- 注册、登录、退出正常。
- 无效 JWT 不能访问受保护接口。
- 两个用户登录后只能看到各自的数据。
- 无权访问其他用户的产品和任务。

### 11.2 产品及知识库

- 可以创建多个产品。
- 不同产品的资料相互独立。
- 上传结果与 RAG 入库结果能够区分。
- 上传失败可以正确提示。
- 页面刷新后数据不丢失。

### 11.3 内容生成

- 能够创建任务并关联正确产品。
- 爆款采集和分析结果正确展示。
- 人工 Prompt 正确参与生成。
- 可以查看文案和图片。
- 能够跟踪工作流实际状态。
- 生成失败后不会误显示成功。

### 11.4 审核及发布

- 文案修改能够持久化。
- 版本记录正确。
- 规则检查结果能够展示。
- 审核动作正确恢复后端工作流。
- 未确认发布时不触发真实发布。
- 发布失败或状态不明确时不会盲目重复发布。

### 11.5 完整业务闭环

至少使用一个测试账号和一个测试产品，完成：

创建产品 → 上传资料 → 内容生成 → 审核修改 → 模拟发布 → 反馈处理 → 下一次生成。

验证人工 Prompt 保持不变，历史经验仅作为下一次生成的参考输入。

真实发布另行验收，需要明确账号及发布内容。

## 12. 前后端接口核对清单

前端开发前，需要对现有 FastAPI 的下列能力进行核对：

| 接口领域 | 需要确认 |
|---|---|
| Auth | 注册字段、登录方式、JWT 生命周期 |
| Products | 产品 CRUD、资料上传、删除语义 |
| RAG | 入库状态与失败信息获取 |
| Tasks | 创建、查询、任务状态枚举 |
| Collectors | 采集触发方式、进度和结果 |
| Analysis | AI 分析触发方式、结果结构 |
| Prompts | Prompt 保存、修改、读取 |
| Rules | 平台规则、自定义规则、检查结果 |
| Workflow | 启动、暂停、审核后恢复 |
| Content | 生成内容、修改及版本记录 |
| Images | 图片生成状态和鉴权读取 |
| Publishers | 确认发布、发布状态、去重 |
| Memory | 发布后指标及经验处理状态 |

**原则：** 前端围绕实际后端契约设计，不在没有接口支持的情况下承诺已经实现的能力。

## 13. 待确认的产品决策

以下内容需要结合现有后端代码核实，不能由前端自行假设：

1. 产品编辑字段及产品删除后的数据处理规则。
2. 支持上传的文件类型、大小和数量。
3. 用户是否能在界面上主动触发 RAG 重新入库。
4. Chrome 采集是任务级自动执行，还是允许用户单独触发。
5. 生图失败后是否支持单独重试。
6. 用户 Prompt 是否支持多模板保存。
7. 审核修改是否自动产生新内容版本。
8. 发布前是否能够识别并显示目标小红书账号。
9. 工作流任务状态如何查询和恢复。
10. 运营指标更新频率及可展示的字段。
11. 自定义规则是否已有完整保存与更新接口。

## 14. 版本验收结论标准

当满足以下条件时，可认为前端 V1.0 完成：

1. 用户能够不借助 Swagger 或命令行完成核心业务操作。
2. 所有核心页面正常调用现有后端接口。
3. 主要工作流从产品创建到审核发布可完整执行。
4. 重要状态能够正确反馈。
5. 不同用户之间不存在越权访问。
6. 错误和失败操作能够被正确处理。
7. 人工审核权和发布确认机制有效。
8. 本地运行环境下完成前后端联调与验收。

**文档结论：** V1.0 前端的重点不是增加更多功能，而是将已经实现的后端能力组织成稳定、清晰、可操作的用户界面。
